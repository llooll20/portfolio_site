# 프로젝트 구조

## 명시될 사항

1. 내 포트폴리오가 들어가야 한다.
2. 나에 대한 전반적인 개요가 한눈에 보여야 한다.
3. 사진, 글과 같은 요소를 게시할 수 있어야 한다.
4. Git으로 해당 프로젝트 작업과 연결되어야 한다.

## 페이지 구성

### 첫 화면

- 이름, 진로, 3줄 소개를 보여준다.
- 아래로 스크롤하면 소개 개요(약 5줄), 이력(학교, 자격증 등), 간단한 포트폴리오 내용을 보여준다.
- 간단한 포트폴리오에는 미션창, Say Something의 이미지와 3줄 요약을 포함한다.

### 본인소개 페이지

- 면접관이 보기 쉽게 학교, 자격증, 성장 배경, 성취 목표를 서술한다.

### 포트폴리오 페이지

- 포트폴리오를 소개하고, 버튼 형태의 프로젝트 이름을 클릭하면 상세 화면으로 이동한다.
- 상세 화면에서는 대표 이미지, 글 소개, 기술 스택, 나의 역할을 보여준다.
- 오른쪽 목록에는 기능, 설계, 구조, 활동(발표, 논문, 저작권 등록) 등의 사실을 보여준다.
- 가능하면 앱 실행 파일(EXE) 또는 설치 파일을 제공한다.
- GitHub 저장소도 연결할 수 있도록 한다.

### 웹 개발용 페이지

- 웹 프로젝트에서 사용할 여러 실험을 위한 빈 공간 페이지다.
- 게임 개발, 웹페이지 상태·환경 점검, 웹 프로그래밍 관련 실험 등을 진행한다.

## 관리 방침

- 현재는 첫 화면, 본인소개, 포트폴리오의 3가지 페이지로 구성한다.
- 이후 특정 페이지의 규모가 커질 경우 분할하여 관리한다.

## 사이트 기본 구조

```text
사용자
    │
도메인
    │
Cloudflare
    │
Vercel (Frontend)
    │
API Server (Render / Railway / Azure)
    │
PostgreSQL
    │
Object Storage (이미지)
```

### 사용자

웹사이트에 접속하는 사람이다.

### 도메인

- 사람이 기억하기 쉬운 인터넷 주소다. 예: `www.naver.com`
- 예: `portfolio.com` → `104.18.xx.xx`

### Cloudflare

- DNS, CDN, 보안을 한 번에 제공하는 서비스다.
- DNS는 어느 서버에 접속해야 하는지 알려준다. 예: `portfolio.com` → Vercel 서버
- CDN은 이미지, CSS, JavaScript를 사용자와 가까운 서버에서 제공한다.
- 보안 기능은 공격을 차단한다.

### Vercel

- React, Next.js 등의 프론트엔드를 배포하는 서버다.
- 사용자가 보게 될 화면을 제공한다.

### API 서버

- 백엔드 서버다.
- 프론트엔드의 요청을 받아 실제 처리를 담당한다.

### PostgreSQL

- 실제 데이터를 저장하는 데이터베이스다.

### Object Storage

- 이미지나 파일을 저장한다.
